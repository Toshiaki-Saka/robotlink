# デモのシナリオ: このアームは何をしようとしているのか

本リポジトリに同梱されているアニメーションとプロットは、いずれも 8 秒間の
シミュレーション 1 回分 (`src/main.cpp`) の結果です。本ドキュメントでは、その実行が
何を示そうとしているのか、なぜアームがこのように動くのか、そして「良い結果」とは
どのようなものかを説明します。

## 一文でいうと

アームは**意図的にずれた姿勢**から開始し、**滑らかで、3 関節すべてが異なる周波数で
動く目標運動**への追従を指令されます。このデモが問うているのは、記号的に導出された
動力学と計算トルク制御が、(a) その初期誤差を素早く、かつオーバーシュートなく
除去できるか、(b) その後、動き続ける目標にほぼ厳密に追従し続けられるか、の 2 点です。

これは**追従 (tracking) のデモ**であり、ピック&プレースや経路計画のデモではありません。
何かを掴むわけでも、障害物やタスク目標があるわけでもありません — 「タスク」は
目標軌道そのものです。

## アームの構成

3 つの回転関節と 2 本の可動リンクです (`include/sim_config.hpp`)。

| 関節 | 名称             | 回転軸                                     |
|------|------------------|--------------------------------------------|
| q1   | 肩ヨー           | 鉛直なベース軸まわりの旋回                 |
| q2   | 肩ピッチ         | 上腕リンクを水平から持ち上げる             |
| q3   | 肘               | 上腕に対して前腕を屈曲させる               |

上腕リンク `L2 = 0.5 m`、`m2 = 1.0 kg`、前腕 `L3 = 0.4 m`、`m3 = 0.7 kg`、重力は −z 方向。
最大到達距離は `L2 + L3 = 0.9 m` です。

## 指令される運動

各関節は、それぞれ独立した正弦波に従います。

```
q_d,i(t) = offset_i + A_i * sin(w_i * t + phi_i)
```

| 関節 | offset (rad) | A (rad) | w (rad/s) | phi | 実際の可動範囲 | 周期 |
|------|--------------|---------|-----------|-----|----------------|------|
| q1   | 0.0          | 0.6     | 0.8       | 0   | −0.60 … +0.60 rad (±34.4°) | 7.85 s |
| q2   | −0.3         | 0.5     | 1.0       | π/4 | −0.80 … +0.20 rad (−45.8°…+11.5°) | 6.28 s |
| q3   | +0.8         | 0.7     | 1.2       | π/2 | +0.10 … +1.50 rad (5.7°…86.0°) | 5.24 s |

平たく言えば、ベースは左右におよそ ±34° **旋回**し、肩はやや下げた姿勢を中心に
**上下に揺れ**、肘はほぼ伸びきった状態と直角の間で**屈伸**します — それらが同時に、
しかしそれぞれ異なる速さで起こります。

3 つの角速度の比が 4 : 5 : 6 であるため、実行中に同じ関節角の組み合わせが繰り返される
ことはありません。パターンが閉じるのは 31.4 s 後なので、8 秒のデモではその約 1/4 が
見えていることになります。したがって手先は、繰り返しのない 3 次元のリサージュ状の
曲線を描き、ベースから 0.48 m 〜 0.90 m の球殻の内側を動き続けます — これが
ビジュアライザーの 3D パネルに描かれる渦を巻いた軌跡です。

## なぜステップ入力や直線ではなく「この」運動なのか

この軌道は、パイプラインのうち**正しく作るのが難しい部分**を実際に働かせるように
選ばれています。

**1. 滑らかなので、コントローラが正当なフィードフォワード項を持てる。** 計算トルク制御は
目標加速度 $\ddot{q}_d$ を入力として必要とします。正弦波は無限回微分可能なので、
`desired_trajectory()` は $q_d$、 $\dot{q}_d$、 $\ddot{q}_d$ を閉じた形で返し、
そのすべてが連続です。ステップ指令ではインパルス的なトルクが要求され、追従品質に
ついては何もわかりません。

**2. 3 関節が同時に、しかも異なる周波数で動く。** これが最大の要点です。1 関節しか
動かない場合や、準静的とみなせるほど遅い運動の場合、コリオリ・遠心力項
$C(q,\dot{q})\dot{q}$ と質量行列 $M(q)$ の姿勢依存性はほとんど表面化しません。しかし
それらこそが、手計算では手間がかかり誤りやすい項であり、本プロジェクトが記号的に
導出している理由そのものです。周波数をずらしてあることで、アームは同期した対称な
姿勢に落ち着かず、連成項は実行中ずっと励起され続けます。生成された動力学に符号の
誤りがあれば、ただちに追従誤差として現れます。

**3. 重力負荷が広い範囲で変化する。** q2 は −45.8° から +11.5° まで、q2 + q3 は −24.5° から
+91.6° まで動くため、アームはほぼ水平に伸びた姿勢 (重力トルク大) と、折りたたまれた
ほぼ鉛直の姿勢 (重力トルク小) の両方を通過します。これにより、重力ベクトル $g(q)$ を
1 つの動作点ではなく可動範囲全体にわたって検証できます。負荷の大半を担う関節 2 の
トルクは、およそ −9.3 … +10.6 N·m の範囲で変動します。

**4. 作業領域の内側に留まり、特異点を避ける。** 肘角は 0.10 … 1.50 rad の範囲に留まり
0 に達しないため、アームが完全に伸びきることはありません (`q3 = 0` は境界特異点です)。
また手先のベース軸からの水平距離が 0.48 m を下回ることもないため、肩軸に近づくことも
ありません。これは意図的なものです — このデモの主題は追従精度なので、特異点近傍の
挙動は対象外としています。(最大到達距離は 0.900 m 中 0.898 m なので、伸びきる寸前
までは近づきます。振幅を大きくする場合はここに注意してください。)

## 意図的に与えられた初期誤差

シミュレーションは次の状態から始まります。

```
q(0)   = [ 0.2, -0.1,  0.3 ] rad     (静止状態、dq(0) = 0)
q_d(0) = [ 0.0,  0.054, 1.5 ] rad
```

つまりアームは、指令された姿勢から **0.2 / 0.15 / 1.2 rad ずれた位置**から始まります。
肘だけで約 69°、手先位置にして 0.57 m の誤差です。これは手抜きではなく、テストの
後半部分にあたります。計算トルク制御は、閉ループ誤差を次の線形系に帰着させると
主張します。

```
e'' + Kd * e' + Kp * e = 0        Kp = 80, Kd = 18  →  極は s = -8, -10
```

これを確かめる唯一の方法は、誤差を与えてその減衰を観察することです。この極配置なら
応答は振動せず、時定数は 1/8 s になるはずです — 実際の実行でもそのとおりで、関節誤差は
t ≈ 0.78 s で 0.01 rad を、t ≈ 1.08 s で 0.001 rad を下回り、オーバーシュートは
ありません (肘の誤差は +1.2 rad から、符号を反転させることなくゼロへ減衰します)。

ビジュアライザーが定常精度を **t = 2 s 以降**でのみ評価している (誤差パネルの点線)
のもこのためです。それ以前のプロットは、意図的に与えた立ち上がりの過渡応答が
支配的だからです。

## 良い結果とはどのようなものか

| ビジュアライザーのパネル | 確認すべきこと |
|--------------------------|----------------|
| q1 / q2 / q3 の時間波形   | 約 0.5 s 以降、実線の「実際値」が破線の「目標値」に重なる |
| 関節誤差 [deg]            | 開始直後に 1 度だけ減衰するピーク、その後はゼロの水平線。リンギングなし |
| トルク [N·m]              | 滑らかな曲線でチャタリングなし。アームが一瞬静止していてもゼロにならない (重力を支える必要があるため) |
| 手先位置誤差 [mm]         | t = 0 で大きく (約 568 mm)、その後ほぼ 0。タイトルに定常 RMS が表示される |
| 3D 軌跡                   | 実際の手先軌跡が、目標の渦状の軌跡の上に乗る |

リファレンス実行では、定常状態の手先 RMS 誤差は約 `5e-5 mm` です。すなわち追従は
積分の丸め誤差レベルまで厳密です。これは想定どおりの結果です — コントローラは
プラントと**同一のモデル**を用いており、外乱もモデル誤差もないため、追従が悪化する
要因が残っていないからです。ここに定常誤差が現れるなら、生成された動力学か
コントローラのどこかが誤っているということであり、この点こそがこのデモを
回帰チェックとして有用にしています。

## 自分の実験に作り変える

上記のすべては `include/sim_config.hpp` の `TrajectoryParams`
(および `src/main.cpp` の初期状態) にあります。編集して再ビルドしてください。

| 変更内容 | 何が確認できるか |
|----------|------------------|
| `A = (0, 0, 0.7)` | 肘のみを動かす。他の関節は、動く肘が生む反力トルクに抗して静止を保たなければならない |
| すべての `w` を 2 倍 | 高速化 → コリオリ・遠心力項とトルクが増大。固定ステップ幅に対する良いストレステスト ([`integration-notes.md`](integration-notes.md) 参照) |
| `A = (0, 0, 0)` | 目標値一定の整定 / 重力保持テストになる |
| `src/main.cpp` の初期状態をさらにずらす | 過渡応答が長くなり、誤差ダイナミクスがより明瞭に見える |
| `CtrlGains` の `Kp`、`Kd` を下げる | 収束が遅くなり、場合によっては振動的になる (極がそれに応じて移動する) |
