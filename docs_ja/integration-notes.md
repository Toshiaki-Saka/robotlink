# 積分に関する注記: なぜここでは固定ステップの RK4 で十分なのか

本ドキュメントでは、RobotLink において固定ステップの4次ルンゲ・クッタ法 (RK4)
積分器を選択した理由と、代わりに適応ソルバーが必要になる場面について説明します。

## 現在の構成

| 項目                         | 値                                     |
|------------------------------|----------------------------------------|
| 手法                         | RK4 (固定ステップ、4次)                |
| 時間刻み `dt`                | 0.005 s (`sim_config.hpp`)             |
| 総ステップ数                 | 1,600 (8 s のシミュレーション)         |
| ステップあたりの関数評価回数 | 4 (`rk4.hpp`)                          |

## RK4 と適応ソルバーの比較

**RK4 (ここで使用)**
- 局所打ち切り誤差 $O(dt^5)$、大域誤差 $O(dt^4)$。
- 固定ステップサイズ: コストが予測可能で、実装が単純。
- 誤差推定がなく、精度の保証もない。

**適応的 Dormand-Prince (例: MATLAB `ode45`、Boost.Odeint `runge_kutta_dopri5`)**
- 4次と5次の解を計算し、その差を用いて局所誤差を推定する。
- 要求された許容誤差 (例: `RelTol = 1e-3`、`AbsTol = 1e-6`) を満たすように
  `dt` を自動的に縮小または拡大する。
- ステップあたり約6回の関数評価 (FSAL 特性により実質的には5回)。

## なぜこのアームには RK4 で十分なのか

閉ループ系は $K_p = 80$、$K_d = 18$ の計算トルク制御を用いており、
これにより誤差ダイナミクスが線形化される:

```
s^2 + 18 s + 80 = 0   →   s = -8, -10
```

RK4 の安定領域は、おおよそ $|\lambda \cdot dt| \le 2.79$ を要求する。ここでは:

- $\lambda = -8$,  $dt = 0.005$  →  $\lambda \cdot dt = -0.04$  — 余裕をもって安定
- $\lambda = -10$, $dt = 0.005$  →  $\lambda \cdot dt = -0.05$  — 余裕をもって安定

最速の参照軌道周波数は `ω = 1.2 rad/s` であり、1振動周期あたり
おおよそ1000点の積分点が得られる。この系は滑らかで非剛性(非スティッフ)であるため、
固定ステップでも十分すぎるほど正確である。

## どのような場合に適応ソルバーへ切り替えるか

| 状況                                | 固定ステップ RK4 ($dt = 0.005$) | 適応ソルバー              |
|-------------------------------------|-----------------------------|---------------------------|
| このアーム (滑らか、非剛性)         | 正確                        | 同等、ほとんど利得なし    |
| 高ゲイン / 剛性(スティッフ)系 ($K_p \gg 80$)  | より小さな `dt` が必要      | `dt` を自動的に縮小       |
| 不連続な外乱 / 接触                 | 精度が劣化                  | ステップ制御が対応        |
| 誤差限界の保証が必要                | 保証なし                    | 許容誤差を指定可能        |

## 接触・衝突のケース

よくある混同点として、二足歩行シミュレーションはしばしば適応ソルバーを*必要とする*
一方で、このアームは必要としない。その理由はソルバー自体ではなく、**不連続性**にある:

- **歩行**: 足と地面の接触は脚の速度を不連続に変化させる
  (衝撃方程式)。右辺 $f(x, t)$ に不連続点が存在する。固定ステップは
  それらを横切って直進的に積分してしまい、大きな誤差を蓄積する。
  適応ソルバーは**イベント検出** (ゼロクロッシング) を追加することで、
  ステップを衝撃の瞬間に正確に止め、状態をリセットできる。

- **このアーム**: 環境との接触がない。状態 $[q, \dot{q}]$
  と右辺 (ダイナミクス + 計算トルク) は時間に関して滑らかである。RK4 が
  前提とする十分に滑らかな解という仮定が成り立つ。

**経験則**

> 滑らかな系で不連続なイベントがない → 固定ステップの RK4 で十分。
>
> 接触、衝突、または切り替えがある → イベント検出を伴う適応ステップを使用する。

ゲインを大幅に上げる場合 (たとえば $K_p > 500$) や、衝突・接触力を追加する場合は、
Boost.Odeint の `runge_kutta_dopri5` のような適応的 Dormand-Prince 積分器への
移行を検討すること。
